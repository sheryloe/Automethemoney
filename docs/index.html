페이퍼 트레이딩 자동화 시스템
설계·구현 포트폴리오

무엇을 구현했는가: 자동 실행·기록·조회가 연결된 운영형 페이퍼 트레이딩 시스템. 어떻게 구현했는가: GitHub-hosted Actions + Supabase + Vercel. 결과는 주기 실행 이력과 실제 운용 수익률로 검증 가능한 형태로 정리했습니다.

담당 역할: 실행 파이프라인 설계, 데이터 구조 정의, 운영 화면 연동, 성과 추적 기준 수립
구현 대상 페이퍼 트레이딩 자동화
실행 계층 Actions 스케줄 배치
데이터 계층 Supabase 상태 이력
조회 계층 Vercel 운영 대시보드
기술 면접관 기준: 구현 단위, 책임 단위, 성과 지표가 분리되도록 구조화

Step 1~5 구현 흐름

1

문제 정의: 수동 운영 한계 식별

수동 실행 방식은 주기 누락과 상태 추적 단절이 발생해 운영 신뢰도가 낮았습니다.

입력: 수동 실행 이슈 / 처리: 자동화 대상 식별 / 산출: 주기 실행 필요조건 정의

2

실행 파이프라인 설계

GitHub-hosted Actions 스케줄 기반으로 배치 진입점을 고정해 반복 실행 구조를 만들었습니다.

입력: 스케줄 조건 / 처리: 배치 트리거 및 실행 / 산출: 자동 사이클 수행 로그

3

데이터 모델링 및 추적 기준

하트비트·설정·포지션·일일 성과를 분리 저장해 변경 이력과 상태 검증이 가능하도록 구성했습니다.

입력: 실행 결과 데이터 / 처리: 테이블별 정규 저장 / 산출: 추적 가능한 상태 이력

4

운영 UI 구성

Vercel 대시보드에서 실행 상태, 포지션, 성과 지표를 한 화면에서 확인하도록 구성했습니다.

입력: Supabase 기록 / 처리: 조회 화면 매핑 / 산출: 운영 판단용 대시보드

5

실운용 성과 추적

주간/월간 단위 성과를 분리 관리해 자동화 구조의 실전 운용 가능성을 확인했습니다.

입력: 실운용 결과 / 처리: 월간·누적 수익률 집계 / 산출: 성과 기반 운영 판단

아키텍처 다이어그램 (증빙)

핵심 흐름: 트리거(Actions) → 계산(Batch) → 저장(Supabase) → 확인(Vercel UI)

실제 운용 성과

운용 상태
1개월
누적 수익률
